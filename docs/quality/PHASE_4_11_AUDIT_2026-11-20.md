## P1 findings

### F-01 — CP-SAT runs synchronously inside the async API event loop

- **File:** `backend/app/modules/timetables/router.py:114`
- **Precondition:** authorized actor calls `POST /api/v1/admin/timetables/jobs` with a hard
  solve limit or a large snapshot.
- **Impact:** bounded solver time does not bound event-loop blocking; the request can monopolize
  the process, delay health/session/database requests and degrade availability.
- **Evidence:** `solve_timetable()` is CPU-bound CP-SAT; the router calls it directly in the
  async handler.
- **Smallest fix:** offload one solve to a dedicated worker/process or `asyncio.to_thread` only
  with bounded queue/concurrency. Return queued/running promptly and keep result status truthful.
- **Regression:** synthetic 300-second request with queue overflow must remain responsive and
  cancel/timeout predictably.

### F-02 — Timetable job and version list endpoints do not scope returned rows

- **File:** `backend/app/modules/timetables/router.py:192` and `:212`
- **Precondition:** an actor with global timetable read permission; either list endpoint is called.
- **Impact:** rows from every school/year can be returned despite year/school data boundaries.
- **Evidence:** both endpoints use `Scope()` and query every `TimetableJob` or
  `TimetableVersion` without a `school_id`/`academic_year_id` filter.
- **Smallest fix:** require explicit optional scope arguments, enforce exact scope against the
  principal, and add matching SQL `WHERE` clauses before returning.
- **Regression:** seed rows in two synthetic schools and verify one-scoped actor receives only
  matching job/version IDs.

### F-03 — Import commit is not protected against concurrent first-commit replay

- **File:** `backend/app/modules/students/router.py:494`
- **Precondition:** two requests concurrently commit the same ready batch.
- **Impact:** both sessions can observe a non-committed state and mutate/create or lock records;
  no `FOR UPDATE` or compare-and-set protects the batch state.
- **Evidence:** the endpoint checks `batch.state`, but loads the batch without row locking and
  does not atomically transition preview/ready to committed.
- **Smallest fix:** re-fetch batch with `SELECT ... FOR UPDATE`, atomically reserve
  `preview/ready -> committed`, and keep idempotency replay on the committed state.
- **Regression:** isolated PostgreSQL two-session commit test must produce one mutation, one
  replay response and no duplicate audit or enrollment.

### F-04 — Solver can accept client-supplied closed slots instead of server-composed closures

- **File:** `backend/app/modules/timetables/router.py:74`,
  `backend/app/modules/timetables/solver.py:93`
- **Precondition:** a caller has timetable create permission and supplies a wrong/empty
  `closed_slot_ids` value.
- **Impact:** a schedule may ignore actual school holidays or closed calendar ranges, violating
  the timetable closure requirement.
- **Evidence:** no school-holiday lookup or calendar-slot derivation occurs in the API; the
  snapshot trusts `body.closed_slot_ids`.
- **Smallest fix:** server fetches approved holidays and template slots by school/year, derives
  closed slots and stores the derived snapshot/checksum. Client cannot omit or add closures.
- **Regression:** seed an active holiday range, solve, and verify no entry is produced on a
  derived closed slot.

## P2 findings

### F-05 — Student import reads the complete upload before enforcing the file limit

- **File:** `backend/app/modules/students/router.py:376`
- **Precondition:** repeated large upload requests before decode checks.
- **Impact:** memory pressure occurs before the 10 MB/100k checks in `decode_csv()`.
- **Smallest fix:** enforce `Content-Length` plus bounded/chunked stream parsing and final byte
  count before staging.

### F-06 — Student bulk export has no audit record

- **File:** `backend/app/modules/students/router.py:627`
- **Precondition:** actor exports a scoped student cohort.
- **Impact:** sensitive bulk read lacks attributable audit evidence required for bulk operations.
- **Smallest fix:** write an audit record in the request transaction or access log with scope,
  checksum/count and actor, no plaintext student data.

### F-07 — Calendar and holiday writes do not write audit evidence

- **File:** `backend/app/modules/school_calendar/router.py:75`,
  `backend/app/modules/school_calendar/router.py:211`
- **Precondition:** template or holiday is created.
- **Impact:** calendar integrity change is not captured in the audit trail.
- **Smallest fix:** use `write_audit_in_transaction()` for create/update/activation with scope,
  checksum and before/after state.

### F-08 — Analytics histogram does not validate bin count before empty-input handling

- **File:** `backend/app/modules/analytics/domain.py:4`
- **Precondition:** caller passes `[]` and `bin_count=0`.
- **Impact:** invalid input returns `[]` rather than raising `BIN_COUNT_REQUIRED`.
- **Smallest fix:** validate `bin_count >= 1` before checking whether values are empty.

### F-09 — Assessment numeric policy accepts NaN/Infinity without a stable policy result

- **File:** `backend/app/modules/examinations/domain.py:40`
- **Precondition:** API or fixture supplies a non-finite float.
- **Impact:** NaN can pass range comparison and inf can raise a decimal conversion error.
- **Smallest fix:** reject non-finite values with an explicit `NOT_FINITE` error before Decimal
  quantization.

### F-10 — ML mean/MAE and snapshot validation do not reject non-finite numbers

- **File:** `backend/app/modules/machine_learning/domain.py:20`
- **Precondition:** feature or metric series contains NaN/Infinity.
- **Impact:** model metrics and baseline values can become non-finite and misleading.
- **Smallest fix:** add finite-value guards to snapshot features, actual values and predictions.

### F-11 — Observability redaction is shallow and key-name-only

- **File:** `backend/app/modules/operations/observability.py:7`
- **Precondition:** nested structures or values containing authorization strings are logged.
- **Impact:** credentials or token text may bypass redaction.
- **Smallest fix:** recursive depth-bounded redaction, key and value pattern handling, plus
  secret-scanner tests.
