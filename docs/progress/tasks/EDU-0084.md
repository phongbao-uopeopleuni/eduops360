# EDU-0084 — Scope timetable list endpoints by school and year

## Scope

Address only EDU-0080 F-02. Add optional school/year filters to the timetable job and
version list endpoints, enforce those exact requested dimensions against the principal,
and filter the database query before returning rows.

Use synthetic records in an isolated disposable PostgreSQL database. Preserve the existing
unscoped behavior for callers with explicitly global permission; do not broaden permissions
or introduce new school policy.

## Pre-edit evidence

- Both list endpoints enforced `Scope()` and queried rows without a school/year predicate.
- The frontend currently calls the job-list endpoint without filters; optional parameters
  preserve its existing global-read behavior while allowing scoped callers to request only
  authorized rows.
- F-02 requires synthetic rows from two schools and verification of job/version isolation.

## Change and verification

- Added optional `school_id` and `academic_year_id` query parameters to both list endpoints.
  The requested scope is passed to the existing permission guard, and each supplied
  dimension is applied as a SQL `WHERE` before rows are returned.
- Updated the generated OpenAPI contract and TypeScript types. Existing callers without
  filters remain compatible; school/year-scoped callers now provide a matching scope.
- Updated `TimetablesPage` to select an initial school/year and include both dimensions in
  subsequent job-list requests. The page reloads jobs when either scope selector changes.
- Added a focused frontend regression test for the scoped job-list URL.
- Fail-first against the original endpoints: the live regression failed because
  `list_timetable_jobs` did not accept `school_id`.
- The isolated PostgreSQL regression seeded two synthetic schools, two years in one school,
  and a year in the other. It verifies school-only and exact school/year results for both
  jobs and versions, plus denial of a cross-school request.
