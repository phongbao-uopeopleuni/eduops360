# EDU-0083 — Serialize concurrent student import commits

## Scope

Address only EDU-0080 F-03: concurrent requests committing the same staged batch must
serialize on the batch row so exactly one transaction mutates data and writes the commit
audit, while the other returns the committed result as an idempotent replay.

Use synthetic records only in an isolated disposable PostgreSQL database. Do not edit the
audit verdict or claim independent review/phase acceptance.

## Pre-edit evidence

- `commit_student_import` loaded a batch with `AsyncSession.get()` and checked `state`
  without a row lock.
- The endpoint mutates student/enrollment rows, marks the batch committed and writes audit
  in one transaction, so the batch state check must serialize with those mutations.
- Docker engine was started for this task. Dedicated Compose project
  `eduops360-edu0083-f03` created its own `eduops360-edu0083-f03_postgres-data` volume.
- Alembic migration service exited `0` against that disposable database. No shared/dev
  database, existing `infra/.env`, credentials or real student records were used.

## Change and verification

- The endpoint now selects the batch with `FOR UPDATE` and `populate_existing=True` before
  checking its state. Student/enrollment writes, state transition and audit remain within
  the endpoint's existing transaction.
- Added a two-independent-session regression using synthetic school/year/class/student and
  a staged batch. It verifies the second query carries `FOR UPDATE`, both calls return the
  same committed batch, one enrollment exists, and one commit audit exists.
- Fail-first against the original implementation: the test failed because the second batch
  query did not contain `FOR UPDATE`.
- Windows-specific test harness adjustment: the first attempt exposed psycopg's requirement
  for a SelectorEventLoop. The test now uses the repository's `create_event_loop()` helper;
  this was a harness issue, not a product-code failure.
- Final live PostgreSQL test: `python -m pytest tests/student_import -q` — **5 passed**.
- The concurrency test also passed three consecutive isolated reruns (**1 passed** each).
- `python -m ruff check backend\app\modules\students\router.py backend\tests\student_import\test_commit_concurrency.py` — passed.
- `python -m ruff format --check backend\app\modules\students\router.py backend\tests\student_import\test_commit_concurrency.py` — passed.
- `git diff --check` — passed.
- Isolated database Alembic head: `0013_timetable_solver`. No migration was added by this task.
- `docker compose -p eduops360-edu0083-f03 down -v --remove-orphans` removed the dedicated
  containers, network and volume; the generated local env file was removed and absence of
  all named test resources was verified.
