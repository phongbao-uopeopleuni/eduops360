# EDU-0085 — Resolve server-derived timetable closure inputs

## Scope

Prepare EDU-0080 F-04 without inventing policy. Do not change solver source until the
canonical Phase 00 decision record establishes how a holiday becomes approved for solver
use and which schedule template is authoritative for a school/year.

## Evidence and blocker

- `SchoolHoliday.status` permits only `draft`, `active`, and `archived`; there is no
  approved state, approver, approval timestamp, or activation route.
- `ScheduleTemplate.status` permits `draft`, `active`, and `archived`, but does not enforce
  a unique active template per school/year.
- `TimetableJobCreate` currently accepts slots and `closed_slot_ids` from the client and
  carries no template identifier.
- Treating `active` as `approved`, selecting one among multiple active templates, or
  converting template-slot IDs to solver-slot IDs would add unconfirmed policy/behavior.
- No source files were changed for F-04. Stop before implementation pending authorized
  Product Owner decisions; do not bypass the block by moving to F-01.

## Decisions required

1. Is `SchoolHoliday.status == "active"` authoritative approval for solver scheduling, or
   must the system add a distinct approved/activation workflow?
2. Is exactly one active `ScheduleTemplate` required per school/year, or should each job
   explicitly identify the active template it uses? Define fail-closed behavior for missing
   or ambiguous selection.

## Product Owner decisions

- `SchoolHoliday.status == "active"` is authoritative for solver closure; no separate approval
  workflow is added by this task.
- Exactly one `ScheduleTemplate.status == "active"` is required per school/year. No active
  template or multiple active templates fail the job with a 422 error.

## Change and verification

- The timetable create endpoint now loads and validates the unique active template and active
  holidays from the database.
- Solver slots and closed slots are derived from server records only. Client-provided
  `slots` and `closed_slot_ids` are forbidden by Pydantic validation.
- The frontend no longer sends solver slots or client-controlled closures.
- Added unit coverage for rejecting client-supplied slots and deriving closures by holiday
  weekdays.
- Added a partial unique PostgreSQL index for one active template per school/year and a
  matching SQLAlchemy model index.
- Added a frontend submit regression proving `slots` and `closed_slot_ids` are absent.
