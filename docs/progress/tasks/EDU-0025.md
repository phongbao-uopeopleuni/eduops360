# EDU-0025 — Authentication session flow

Implemented `/auth/login`, `/auth/me`, `/auth/logout` with no bearer token in response. Session and CSRF values are high entropy; only hashes are stored server-side. Cookies are `Secure`, `HttpOnly` for the session, `SameSite=Strict`, and logout requires a CSRF header matching both cookie and server hash.

Login performs case-normalized lookup, generic failure response, Argon2id verify/rehash, account lockout, bounded in-process burst limiting, TOTP verification for provisioned MFA accounts, and transactional security audit/outbox. Session expiry, account suspension and database revocation are checked on every request.

Evidence: `docs/progress/evidence/EDU-0025/verification.json`. MFA enrollment and recovery are deliberately not activated while encrypted secret custody and named human recovery authorities remain unresolved.

Invitation and reset capabilities are high-entropy, stored only as SHA-256 hashes, expire, reject reuse and never enter audit payloads. Accepting a reset changes the Argon2id password and revokes all active sessions in the same transaction. The raw capability is returned once to an authorized caller for transfer through a future approved channel.
