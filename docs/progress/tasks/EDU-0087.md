# EDU-0087 — Remediate F-01

## Change

`POST /api/v1/admin/timetables/jobs` now executes `solve_timetable()` with AnyIO
`to_thread.run_sync()` and a per-event-loop `CapacityLimiter` limited to two concurrent
CP-SAT solves. The existing job status/result behavior remains unchanged.

## Remaining limitation

This is bounded off-event-loop execution, not a separate durable worker/queue. F-01 is
addressed for request-loop availability while persistent queue infrastructure remains a
separate implementation scope.
